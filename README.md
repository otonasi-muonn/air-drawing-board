# 空中お絵描き掲示板（最小版）

単一HTMLファイル（`index.html`）で動くWebアプリ。ビルド不要。**利用する正規の経路はGitHub PagesのURL**で、展示PCとスマホは同じURLから開く。ファイルを直接開く形は、展示・QR・カメラの正規経路ではない。

## できること
- マウス／タッチ／ペンで描画（8色・太さ3段階・取り消し・全消去）
- カメラ入力（任意）：「カメラで描く」ボタンでMediaPipe Hand LandmarkerをCDNから読み込み、ピンチ（親指＋人差し指）で描画ON/OFF。人差し指の先端がペン、平滑化（One Euro Filter）・ヒステリシス・手を見失ったら線を中断。失敗してもマウス描画は動き続ける
- 掲示板：投稿→運営モードで承認すると一覧表示。運営モードでは承認/非表示/完全削除、バックアップ書き出し（JSON）
- QR持ち帰り：完成時に、描画データを圧縮してURLフラグメント（`#d=...`）に入れたQRを表示。スマホで開くと作品が復元され、長押し or ボタンでPNG保存
- 描画中はQR用データの文字数メーターを表示（1,200文字が持ち帰りの目安）

## 公開方法（GitHub Pages）
1. リポジトリに `index.html` を置く
2. Settings → Pages → Source を GitHub Actions（または branch）にして公開
3. 発行されたGitHub PagesのURLを展示PCで開く。QRの飛び先は「今開いているページのURL」が自動で使われるため、必ずPagesのURLで開いて確認する

`index.html` を直接ブラウザで開いても描画と掲示板の簡易確認はできるが、QRの飛び先が `file://` になり、カメラもHTTPS前提のため、展示や実機確認には使わない。

## 当日の運用
- 展示PCは Chrome で開き、「全画面」ボタン or F11。PCのスリープ・画面オフは切っておく
- カメラを使う場合はネット接続が必要（MediaPipe本体・モデル・QRライブラリをCDNから読む）。会場ネットが不安定なら、カメラなし（タッチ/マウス）でも成立する
- 掲示板のデータはそのPCのブラウザ（localStorage）にだけある。ブラウザを変えたりデータを消すと消えるので、休憩時間などに「バックアップ書き出し」を押しておく
- 投稿した作品は最初は非公開。運営が「運営モード」で承認すると掲示板に出る

## v2での改良（2026-11-01夜）
- 描画を2層キャンバス化（確定ストロークと描画中ストロークを分離）し、速く描いても重くなりにくくした。ポインタの間引きイベント（getCoalescedEvents）も取り込んで線が滑らかに
- パレットを色覚配慮のOkabe-Ito系に変更（黄のみ白背景での視認性のため少し濃く調整）
- 無操作90秒でアトラクト画面（誘引表示）、完了画面は120秒で自動リセット
- 手順表示（①描く ②完成 ③QR）を追加。ボタン類を大きく（最小48px）
- QRは640pxで生成して縮小表示（読み取りやすく）。QRライブラリ未読込時は原因を分けて表示
- 圧縮の読み取りを Safari で不安定な方式から Reader 方式に変更
- カメラ調整用にピンチ比の数値表示を追加（会場でのしきい値確認用）
- 保存失敗（容量上限）でも作品が消えず、エラーを表示するように

## 検証状況（2026-11-01、イア確認分）
- ✅ エンコード/デコード往復（Nodeで実行）：スマイリー156点→URL 280文字で復元一致（量子化誤差内）。量子化を変えた簡略化経路でもスケール不変を確認
- ✅ 破損データの拒否（形式・範囲・個数の検証）
- ✅ 容量の実測：30秒びっしり落書きは約2,650文字でQR上限超過（簡略化しても約2,090文字）。**描画量が多い作品はQRが生成できても読み取り困難な可能性が高く、その場合はアプリが全画面表示（写真持ち帰り）へ誘導する**
- ✅ 両スクリプトの構文チェック
- ⚠️ **未検証**：実機カメラでのピンチ判定・追跡精度、実機スマホ（iPhone/Android）でのQR読み取りとPNG保存、GitHub Pages上での動作。これらは実機で必ず確認すること
- カメラ映像は保存・送信されない（ブラウザ内で処理のみ）。保存されるのは描画データだけ

## 既知の制限
- QRライブラリ・MediaPipeはCDN依存（オフライン会場では描画と掲示板のみ動作）
- 掲示板はPCローカル保存のみで、他端末と同期しない
- localStorage上限のため、作品数が非常に多い場合は古い作品から削除すること
